# BUG-046: 候補学習の読み正規化とsplitの不一致

- **Issue**: #125
- **発見日**: 2026-11-04
- **影響**: `inputKana`のひらがな・カタカナ・結合文字の表記揺れで同じ読みが異なるsplitへ入ったり、重複を別ペアとして扱ったりし得る。
- **原因**: holdout照合には正規化した`pair_key`を使う一方、候補学習の分割hashと重複キーには元の読みを使っていた。
- **修正**: `split_pairs`で読み・chosen・rejectedを正規化してから分割と重複除外を行う。正規化後に同一になるchosen/rejectedは無効として除外する。
- **検証**: 合成例のひらがな・カタカナ・分解形が同一の1ペアになり、等価な表記同士の選好を拒否する回帰テスト。
- **既存実験**: Vの11,865行はすべて元から正規化済み。修正後もtrain8,987 / validation2,878と教師cacheの全ペア対応が不変で、Vの再学習は不要。
- **教訓**: holdout判定・split・重複除外・モデル入力で同じ正規化規則を使う。
