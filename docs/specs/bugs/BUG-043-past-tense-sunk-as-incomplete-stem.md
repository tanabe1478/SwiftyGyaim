# BUG-043: 過去形「見た」が「見たい」の存在で未完成語幹として沈む

- **Issue**: なし
- **発見日**: 2026-09-24
- **影響**: `mita` で学習頻度6の「見た」が29候補中23位に沈み、「満た」が1位になった。同音異義語レビューの採点集合（上位3件）にも入らず、モデルでは救えなかった。ユーザーは完全一致モードへ逃げて確定した。`sita` の「した」（頻度5）も24位、`deta` の「出た」も7位で同じ形。
- **原因**: `isIncompleteStemCompletion` の「い」欠落ルールが、`見た` + `い` = `見たい` を `少な` → `少ない` と同じ形容詞の書きかけと判定し、`incompleteStemPenalty`（-4.0）を与えていた。`exactHomophoneCandidateIndices` も同じ判定で除外する。prefix modeの意図的確定だけを数えるacceptedTop1Rate（0.975）では、完全一致モードへの逃げが分母に入らないため見えなかった。全確定経路の `Commit outcome` ログで `prefixRank:23` / `inScoredSet:false` として観測できた。
- **修正**: `た` / `だ` で終わる語を「い」欠落ルールの対象外にした（Swift / Python evaluator両方）。「Xたい」は希望の助動詞で、Xたは完成した過去形。`冷た` → `冷たい` のような「た」終わり形容詞語幹は抑制されなくなるが、過去形は全動詞で出るため優先した。`少な` / `くださ` / `っ` 終わりの抑制は維持。
- **検証**: `IncompleteStemPastTenseTests` に `見た/見たい`・`した/したい` の判定と、実ログ数値での `mita` 並び順テストを追加。eval fixture `incomplete-stem-mita-past-001` とともに、修正前のコードで失敗することを確認した。実機では修正後に `mita` の「見た」が1位、`sita` の「した」が24位→2位。
- **教訓**: 集計の分母から逃げ道（完全一致モード・かな確定・Google）を落とすと、heuristic 側の大きな誤りほど見えなくなる。モデル寄与の議論の前に、確定語がモデルの採点集合に入っていたかを確認する。BUG-025 と同じく、「候補集合内の別候補を根拠に penalize する」規則は根拠側の語の正当性を仮定しがち。
