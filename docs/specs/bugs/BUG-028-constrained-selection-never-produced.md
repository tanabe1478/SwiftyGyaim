# BUG-028: 辞書制約付き選択が一度も候補を出せていなかった

- **発見日**: 2026-07-14
- **症状**: dogfoodで「Tabの候補が悪すぎる」との報告。ログ確認で全Tab実行が `zenzGenerated=0`、`Zenz constrained score` ログ0件と判明。#67の辞書制約付き選択は稼働以来一度も候補を追加できておらず、同時に自由生成もopt-out化していたため、Tabのモデル貢献が実質無効化されていた。
- **影響**: Tab候補の品質低下（lattice+補完のみ）。機能がエラーなく「静かに空振り」するため、confirmed動作確認をするまで気づけなかった。
- **原因**: `constrainedCompositions` が列挙を12件でキャップした**後に**呼び出し側で既存候補を除外していた。有界列挙は通常検索と同じ辞書を同じ順で辿るため、最初の12件はほぼ既存候補と同一で、除外後はほぼ常に空になる。
- **修正**: 除外集合を列挙の内側に渡し（`excluding:` パラメータ）、既存表層はスロットを消費せずスキップして「未知の合成」だけで枠を埋めるようにした。空振り時の観測ログも追加。
- **検証**: `ConnectionDictTests` に除外がスロットを消費しないことのテストを追加。dogfoodでTab時の `Zenz constrained score` ログ出現を確認する。
- **教訓**: 「上限付き列挙 → 後段フィルタ」は、列挙順とフィルタ対象が相関していると全滅する。除外条件は列挙の内側へ。また新機能は「エラーが出ない」ではなく「**効果が出ているログ**」で稼働確認する（今回0件ログを3日見逃した）。
