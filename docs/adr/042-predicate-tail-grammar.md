# ADR-042: 1 回の変換は「内容語 1 つ + ひらがなの後続」まで組み上げる

## Status

Accepted (2026-11-11)

## Decision

接続辞書が 1 回の変換で組み上げる単位を「内容語 1 つ + ひらがなで書く後続の連なり」と定める。対象は用言（動詞・形容詞・形容動詞・サ変名詞 + する）の活用形に続く助動詞・接続助詞・終助詞・補助用言・形式名詞。

- 仕様は表で持つ。`Tests/GyaimTests/GrammarCoverageMatrix*.swift` が活用形 × 後続の全組み合わせ（5,264 セル）を定義し、`GrammarCoverageTests` が全セルの合成を検査する
- 後続の行は `Resources/grammar-dict.txt` に置く。`Tools/dict/build-grammar-dict.py` が生成する（369 行）。ADR-041 の 4 行（連用形 + なる）もここへ移す
- `# @tail` を持つ辞書ファイルのエントリを通った結果は、辞書だけで組めた結果の後ろに出す（`ConnectionDict.searchDetailed`、上限 200 件）
- 取り込んだ接続辞書（`~/.gyaim/connectiondict.txt`）が有効な間は `grammar-dict.txt` を読まない

名詞 + 助詞と、内容語が 2 つ以上の連なりは対象にしない。

## Context

「眠くなる」（ADR-041）に続いて「補完されるべき」「使用するべき」が出ないという報告があり、語ごとに足す対症療法をやめて線引きから決めることにした。

活用形 × 後続を総当たりする表を作って現状を測ると、用言 2,117 通りのうち合成できたのは 54% だった。穴は設計ではなく書き漏らしで、規則性がない。

- 終止形の後ろは と / から / ので / か が通り、けど / し / ね / こと / とき / ため / はず / べき は全滅。のが は通り のは は通らない
- 促音便の動詞（使う・取る・待つ）だけ てます / てみる / てください / たので が切れる。`*った` の後ろに何も続かないため
- 一段動詞だけ ば / ず で終われない（`dict.txt` の行が `*れば*` / `*ず*` で、終端になれない）
- 書きやすい が出ない（連用形の後ろの `やす*` が空のクラス 83 へ出ている）
- 形容詞は 高いです / 高いので / 高くない、形容動詞は 静かだった / ではない / なので が出ない

実ログ（2026-11-09〜11、確定 4,146 回）で候補が出なかった文法的な失敗は 思ってます / 答えれば / 良さそう / 使ってて / 書くために で、すべて用言の後続だった。

## Consideration

- 単位を「内容語 1 つ + ひらがなの後続」とする理由: 後続がすべてひらがなで決まっていれば、選ぶのは内容語の表記 1 か所で済む。Gyaim には文節の区切り直しがないので、選択が 1 か所の範囲が 1 回で変換できる上限になる。内容語が 2 つ入ると候補が組み合わせになり、片方だけ直す手段がない
- 名詞 + 助詞を入れない理由: 助詞 40 行を名詞の後ろに足す試作では、`kaig` の先頭が 会議 ではなく 回が / 会が になり、`hasin` の候補が 12 件から 110 件に増えた。用言は活用語尾が語の切れ目になるので、この汚れ方をしない
- 語ごとに行を足す（ADR-041 のやり方を続ける）: 報告のたびに 1 件ずつ直すことになり、収束しない
- `dict.txt` に直接書く: Gictionary を取り込み直すと消える。取り込み結果との同一性テストもあり、コメントを書けない
- 後続の候補の出し方: 追加した行をそのまま辞書順に出すと、`settei`（競って + い…）で 設定 が 28 位、`naiyou`（ない + よう…）で 内容 が 34 位に落ちた（タイピングシミュレーション）。後続を通った結果を辞書だけの結果の後ろに回すと、辞書だけの結果は順序も件数も変わらない。前方一致の先読みを後続では止める案もあるが、読みが完全に一致する衝突は残るので採らなかった
- 取り込んだ辞書との併用: 取り込みはクラス番号を出現順に振り直す。番号がずれると誤った接続になり、独自クラス 224〜232 と衝突する恐れもあるので読まない。ADR-030 / 041 の行が取り込みで消えていたのと同じ結果で、退行ではない

## Consequences

タイピングシミュレーション（学習なし、モデルあり）:

| コーパス / 区切り | 1 位率 | 候補なし | 操作回数 |
|---|---|---|---|
| 本コーパス 64 文 / 普段 | 0.904 → 0.904 | 6 → 6 | 830 → 830 |
| 本コーパス 64 文 / 自然 | 0.876 → 0.892 | 13 → 10 | 654 → 651 |
| 保留コーパス 20 文 / 普段 | 0.880 → 0.893 | 1 → 0 | 257 → 256 |
| 保留コーパス 20 文 / 自然 | 0.890 → 0.904 | 1 → 0 | 244 → 243 |

- 新しく出るようになった語: 良いところ / 悪いところ / 調べたけど / 分かりにくい。悪くなった語はない
- 検索時間は差が測れなかった。Debug ビルドの `DictionarySearchBenchmarkTests` を文法辞書あり / なしで交互に 4 回ずつ走らせた最小値で、`WordSearch` 前方一致（学習辞書 5,000 件 + Mozc）の平均が 11.6 ms（なし）/ 10.5 ms（あり）。同じ条件での揺れのほうが大きい。Release では測っていない
- 行は読みを最後まで打ったときだけ一致する。文法的に誤った形（静かならしい、高さそう）も組めるが、その読みを打たない限り現れない
- 名詞 + になる（医者になる）と 副詞 + 動詞（どうすれば）は出ない。名詞・副詞から先へ続く行がないため
- 合成候補が並べ替え後に何位に来るかは、シミュレーションの範囲でしか見ていない
