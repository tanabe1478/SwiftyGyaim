# ADR-031: 同音異義語レビューの採点を6件・最小入力長3文字に広げる

## Status

Accepted (2026-09-24). 採点件数は ADR-032 で全件採点に置き換え（最小入力長3は存続）

## Decision

- `aiRerankExactHomophoneMaxCandidates` の既定を 3 → 6（上限6は据え置き）
- `aiRerankFastContextModelMinInputLength` の既定を 4 → 3

通常review（非同音異義語）の入力長ゲート `aiRerankFastContextNormalReviewMinInputLength`（既定5）、頻度ガード、先頭選定、合流待ち（30ms）は変更しない。ADR-028 の「採点集合は既存の上位3件」を置き換える。

## Context

タイピングシミュレータ（`Tools/eval/run-typing-simulation.sh`、64文、学習辞書なし）で、文脈があるのに正解の同音異義語が heuristic 順の4〜8位にあり、モデルの採点集合（上位3件）に入らない取りこぼしが目立った（変える: カエル/帰る/蛙の下、効く、待つ、変えた）。また3文字の読み（`kai` 会/回、`hou` 方/法、`ooi` 多い/大井、`iku` 行く/幾）は入力長ゲート4でモデルに届かなかった。

| 条件 | 普段の区切り 1位率 | 自然な区切り 1位率 | 操作回数（普段） | 採点時間 平均 / p95 |
|---|---|---|---|---|
| 既定（3件・4文字） | 0.838 | 0.757 | 864 | 6.0 / 28 ms |
| 6件 | 0.853 | 0.773 | 847 | 6.9 / 35 ms |
| 3文字 | 0.858 | 0.773 | 860 | 6.2 / 30 ms |
| 両方（採用） | 0.878 | 0.789 | 840 | 8.5 / 37 ms |

heuristic 単独の1位率はどの条件でも 0.777。モデルの上乗せは +6.1 → +10.1 ポイント。悪化は1件（量が1→2位）。

## Consideration

- 採点件数を増やさず頻度ガードを弱める: BUG-036 の誤上書きが戻る。今回の取りこぼしは頻度ではなく採点集合の外にあることが原因。
- 3文字ゲートを同音異義語だけに適用する: 現状、3文字の入力でモデルが走るのは同音異義語レビューだけ（通常reviewは5文字ゲート）なので、グローバルゲートを下げても同じ効果になる。
- 採点を全候補に広げる: 未採点候補との比較が不公平になり（BUG-029）、遅延も増える。上限は既存の6件に留める。

## Consequences

- 採点時間の p95 がシミュレータ（Debugビルドのテストプロセス）で 28 → 37ms。Space の合流待ち30msを超える場合は heuristic 順で確定する。Release の実機での値は未計測。
- 3文字入力でもモデルが走るため、打鍵あたりのバックグラウンド計算が増える。
- コーパスは失敗を見た上で条件を選んだもので、数値は楽観的な可能性がある。dogfood の `commitDiagnostics`（miss の `inScoredSet`）と `modelEffect.netImproved` で確認する。
