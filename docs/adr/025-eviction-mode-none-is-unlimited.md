# ADR-025: 淘汰方式「淘汰なし」は上限を設けず全件保持する

## Status

Accepted（ADR-014 の「全モード共通で上限10,000件」を「淘汰なし」について改める）

## Decision

`EvictionMode.none`（設定画面の「淘汰なし」）では studyDict の件数上限を適用しない。`evict()` は何もせず、学習した語はすべて保持される。MRU とスコアベースは従来どおり上限10,000件。

## Context

ADR-014 は3方式すべてに上限10,000件を課し、「淘汰なし」を「末尾切り捨てのみ」と定義していた。しかし実装上 `study()` は方式に関係なく再学習した語を先頭へ移動するため、「淘汰なし」は MRU と完全に同じ挙動になっていた。enum のコメント（`No eviction (unlimited)`）と設定画面のラベル「淘汰なし」はどちらも無制限を意味しており、ユーザーが選んだ結果と実際の挙動が食い違っていた。

## Consideration

- ラベルとコメントを実装に合わせて「MRUと同じ」と書き換える案: 選択肢として意味がなくなり、セグメントを残す理由もなくなる。
- 上限を撤廃する案（採用）: SKK と同じ方針。studyDict は起動時に全件メモリ読み込みだが、1エントリ数十バイトなので10万件でも数MB。検索は線形走査だが、既存の `search()` は limit=0 で全件を対象にしており、大きな辞書を選ぶかどうかはユーザーの判断に委ねる。

## Consequences

- 「淘汰なし」を選ぶと studydict.txt は増え続ける。ユーザーが意図して選ぶ設定なので許容する。
- 設定画面のヒント文を「淘汰なし: 上限なしで全件保持」に変更した。
- `WordSearchTests` に、上限を超えても切り詰めないこと（none）と切り詰めること（mru）を、事前生成ファイルで検証するテストを追加した。
