# ADR-038: 遠くの別位置から同じ矩形に戻るキャレット矩形は固定矩形とみなし、直前の実キャレットを使う

## Status

Accepted (2026-11-03)。ADR-018 の判定（原点付近かつ 1 px 幅）に 2 つ目の判定を足す。ADR-018 は有効のまま。

## Decision

`showWindow()` で `attributes(forCharacterIndex:lineHeightRectangle:)` が返した矩形を、クライアントの bundle ごとにプロセス全体で持つ `StaleCaretRectDetector` に記録する。次の条件をすべて満たす矩形は固定矩形とみなし、直前に報告された別の矩形（最後の実キャレット）を表示位置に使う（`source=repeatedStale`）。

- 同じ (x, y, 高さ) の矩形が 60 秒以内に報告済み
- 直前に報告された矩形がそれと別で、300 px 以上離れている
- 直前の矩形と行の高さが 2 px 以上違う

固定矩形が続く間は置き換えを維持する。ADR-018 の原点付近の判定が先で、その判定に当たる矩形はこの検出器に通さない。`lastValidCandidateLineRect` は置き換えた矩形では更新しない。

あわせて `showWindow:` の info ログは、直前のログ行と内容が同じなら出さない。

## Context

Chrome の Google Docs で候補ウィンドウがキャレットから離れた場所に出る（`docs/internal/dogfood-conversion-complaints-2026-10.md` ケース 3）。ADR-018 で `showWindow:` ログを info に上げて 15 日分（81,092 行）を見たところ、Chrome だけで 2 系統の矩形が交互に返っていた。

- 固定矩形: 高さ 17〜20、x が Chrome ウィンドウの左端（0、756、1504 = 3008/2）、y が固定（808 か 1521）。文字を打っても動かない
- 実キャレット: 高さ 22〜27（10/21 は 45）、x が入力に合わせて進む

日によって Chrome での入力の半分前後が固定矩形で始まり、実キャレットとの距離の中央値は 650〜1,170 px。矩形は 1 回の入力（変換開始〜確定）の中では変わらず、入力の開始時点でどちらになるかが決まる。Google Docs がキー入力を受けるためのオフスクリーン要素の矩形を返している瞬間があると解釈しているが、Chrome 側の確認はしていない。ADR-018 の条件は原点付近に限るため素通りしていた。

## Consideration

- bundle を Chrome に限定する: 条件が一般的な形で書けたので限定しない。15 日分のログに上の 3 条件を当てると Chrome で固定矩形から始まった入力 545 件中 514 件（94%）に当たり、ghostty（3,584 run）、Slack（3,435）、Discord、VS Code、Chrome の PWA では 0 件だった。
- 「同じ矩形が繰り返し返る」だけで判定する: ghostty の TUI（入力欄の先頭）でキャレットが本当に同じ位置に戻るので 554 件誤検出する。距離と高さの条件で切り分ける。
- 距離だけ（高さを見ない）: Chrome の PWA で同じ行の 15 px 違いの矩形が、窓内の遠い矩形を根拠に誤検出された。直前の矩形と直接比べ、高さの差も要求する。
- 高さだけ: Google Docs のズームで実キャレットの高さは変わる（17〜45）ので、高さの絶対値では決められない。差だけを使う。
- 置き換え先: 直前の実キャレット。直後に打った語の幅だけ左にずれるが、600〜1,200 px のずれよりはるかに小さい。マウス位置は ADR-018 のとおり不自然になりやすい。
- 繰り返し回数を 2 回以上要求する: 誤検出は増えないが再現率が 72% に落ちる。1 回で十分。
- コントローラ単位で持つ: 固定矩形は新しいコントローラの最初の入力から出る（10/21 12:39:00）。`CommittedContextStore` と同じく bundle ごとにプロセス全体で持つ。
- 別の index で矩形を取り直す実験: 先に判定で直せる範囲を直し、残る 6% と置き換え先のずれが気になれば試す。

## Consequences

- Google Docs の固定矩形で始まる入力の大半で、候補ウィンドウが直前のキャレット付近に出る。最初の入力（比較対象が無い）と、60 秒以上あいた後の最初の入力は従来どおり。
- 実キャレットが 60 秒以内に、300 px 以上離れた高さの違う行から同じピクセル位置に戻った場合（クリックで同じ位置に戻るなど）は、ウィンドウが離れる前の位置に出る。ログ 15 日分では観測していない。
- `showWindow:` ログは変化点だけになり、同じ矩形の繰り返し（81,092 行の大半）が消える。
- 設定キーは追加しない。
